# 多端适配设计规范（Responsive Design）

> ← [SKILL 主索引](../SKILL.md) · [hard-constraints.md](hard-constraints.md)（真源，本文件与其冲突时以真源为准）
>
> 适用场景：设计师交付了 **PC 端（1920px 基准画布）设计稿**，需要约定这个页面在**其他屏幕宽度下长什么样**——换布局、换交互，还是只缩小。本文件定义这套约定的**判定方法、声明格式和验收清单**；实现层（`respond` mixin / `useScreen`）见 [../../opendesign-application/SKILL.md](../../opendesign-application/SKILL.md)。
>
> 证据基础：多站代码普查（约 900 个组件）+ 两套同引擎线上门户 30 页的浏览器截图逐页比对。调研素材不随 skill 分发，本文件只保留结论。

---

## 1. 三种适配方式：先分类，再动手

拿到 PC 稿后，对**每个楼层**判断用哪种方式适配。三种方式的成本和交付物完全不同：

| 方式 | 定义 | 设计交付物 | 什么时候用 |
|---|---|---|---|
| **流式（fluid）** | 字号、间距、列数按 token 自动压缩，结构不变 | 只交 PC 稿，无额外交付 | 内容靠「卡片列数减少」就能放下（3 列→2 列→1 列），交互方式不变 |
| **断点换版（adaptive）** | 断点以下，楼层的结构和交互方式整体换成另一套 | PC 稿 + **换版声明**（本文件 §3） | 交互方式放不下，或者换一种形态体验更好（见 §2） |
| **功能降级（degradation）** | 断点以下某功能没有替代物，明确砍掉 | PC 稿 + **降级声明**（必须写出来） | 做替代物的成本超过该功能在手机上的价值（如楼层内锚点导航） |

> 🔴 **没有第四种「悄悄隐藏」**：只写 `display:none`、不给替代物、也不声明砍掉——谁也说不清这是故意的还是忘了。
>
> **降级的定性**：降级本身是**正当的设计选择**——线上门户把页脚在手机上做极简（只留社交图标和法律链接）、全站统一执行，这显然是设计决策不是疏漏。`degrades` 声明的意义**不是禁止降级**，而是把「这是故意的」白纸黑字写下来：生成的页面里看不出「故意的」和「忘了的」的区别，下游（拿需求单生成页面的 AI、复用模板的工程师）会把降级误当缺陷去「修复」，或在同类页面漏掉同样的降级。**隐藏要么给替代物，要么进降级声明，二选一。**

**两个极端判例**（防止一刀切）：

- **纯文字页几乎不用适配**：协议、长文类页面只有一列居中文字时，840 断点处只改字号和内边距就够了（线上实测：某协议页 841↔840 的唯一差异是标题字号小 2px，到 600 才整体换字号）——没有结构的楼层允许只走字号档，不必硬造换版。
- **不带图的卡片几乎不用裁剪；硬扛到底同样是缺陷**：卡片没有封面图、字段少且不折行时（如课程列表卡），1920→375 可以一个字段都不删；带图、多字段的卡片才是降级声明的重点。反面是「一个都不删硬撑到底」——多列参数表靠缩小字号撑到 375 宽，字小到读不了（内容还在，可读性没了），该换形态就换。

## 2. 换版判据（什么内容该换版、在哪条断点换）

### 2.1 换版断点只有两条可选

**840px（`lePadV` / `<=pad_v`）是断点换版的默认线**；**600px（`isPhone` / `phone`）只在 840 断点换完还不够时叠加**（换交互：hover→click、滑动间距、触控目标放大）。

> 调查结论：代码普查和线上 30 页截图都收敛到 840+600——线上样本 100% 在 841↔840 之间整体换版（多数是两套模板、两套 DOM，不是 CSS 重排，连标题文案、默认选中状态都可以不同），600 只调列数和密度；1200/1680/1920 三条线**没有一处**承担结构职责（只管流式压缩、栅格、图片尺寸）。**同一页面/同一楼层禁止混用两条线**（反面教材：同页两条等价的分隔线，一条用 600 换版、一条用 840 换版）。
>
> 600 线除了交互差异，还可以承担**同一功能的两档形态**：如目录抽屉在 840 是推挤式（无遮罩、正文右移），到 600 变覆盖式 + 灰遮罩（70vw）——功能没换、呈现方式分档。

### 2.2 触发换版的信号（按优先级）

| # | 信号 | 说明 |
|---|---|---|
| 1 | **触控可达性** | 只有 hover 才能触达的内容（下拉、tooltip、放大预览）→ 840 以下必须有点击/常显的替代物 |
| 2 | **信息密度放不下** | 横向平铺的筛选区、表格、多列操作在 840 宽度溢出 → 收进弹层或换卡片流 |
| 3 | **操作可达性** | PC 的悬停/右键路径在触屏上没有对应手势 → 换交互（600 线，叠在 840 之上） |
| 4 | **内容优先级** | 次要信息（统计条、配图、面包屑）→ 流式能消化就流式，换版是最后手段 |
| 5 | **指针媒体特性** | `(hover: hover)` / `(pointer)` 与宽度线**各自独立使用**——线上引擎 hover 特性查询 200+ 次，触屏去掉 hover 态是正式的一档，不是宽度线的附属 |
| 6 | **组件几何约束** | 固定宽度的控件装不下时可能提前触发降级（如分页器恒 756px、841 宽时容器 793px 已经塞满）；但同款控件也有空间充足仍按断点降级的实例——**降级时机不能只按容器宽度估算** |
| 7 | **数据条数** | 数据少时直接换形态（<4 条卡片化）在多站出现；形态由数据而非断点驱动时，要在声明里写明 |

### 2.3 中间档（841–1200）的归属

**841–1200px 归 PC 侧简化**：用 PC 结构 + 流式 token（列数减少、字号压缩）。**不出独立设计稿**。只有某功能在 1080px 宽度下已经明确不可用时（如三列卡片+平铺筛选挤不下），才考虑把该功能的断点上移到 1200——**上移必须写进该楼层的换版声明，且和同页其他楼层对齐后才能定**（线上踩坑：同页一个楼层 840 换版、相邻楼层 1200 换版，841–1200 区间两侧视觉撕裂）。

> ⚠️ **中间带质量警示**（线上实测）：841–1080 是质量最差的区间——桌面结构硬扛窄容器时，宽表格被挤到逐字竖排、文字断词（品牌名/型号断成两行）、胶囊文字溢出背景；甚至有「断点之上反而更破」的倒挂（双栏把正文表格压到被裁切，切到移动单栏后反而完整）。**这个区间的表格和宽组件必须有明确的降级策略（裁列或提前横向滚动），不能靠挤压硬扛**。

## 3. 换版声明格式（楼层工单新增 `adaptive` 字段）

要换版的楼层必须在**楼层工单**里写清楚，格式：

```yaml
# ========== 楼层工单：features ==========
floor_id: features
type: card-grid
adaptive:                        # 纯流式的楼层省略本节（走 token 映射）
  breakpoint: 840             # 只能填 840|600|840+600；840+600 表示双线
  capabilities:              # 逐项声明移动端形态；没出现在本表里的能力 = 流式
    - name: 筛选区
      pc: 平铺 ORadioGroup（3 列）
      mobile: ODialog 抽屉（「筛选」按钮唤起，含重置）
    - name: 分页
      pc: OPagination
      mobile: 触底加载（滚动到底自动追加 10 条）
    - name: 下载白皮书按钮
      pc: 楼层标题右侧
      mobile: 保留（移到卡片流下方，全宽）
  degrades:                  # 明确砍掉的功能（无替代物）；空列表 = 无降级
    - name: 锚点导航
      reason: 移动端楼层短，无需楼层内跳转
```

**字段规则**：
- `adaptive.breakpoint` 不填默认 840；填 600 或 1200 必须附**理由**（对应 §2.2 信号表 #1–#3）
- `capabilities` 只列**结构和交互有变化**的能力；纯字号/间距变化不进本表
- 每项的 `mobile` 优先从 **§4 替换模式库**选；库里没有的写自定义描述，并在交付说明中标注「自定义换版形态，需确认」
- `capabilities` 允许记**反向增强**：移动端比 PC 多出来的入口（独有的 tab、PC 没有的楼层标题、悬浮发帖按钮等）——适配不是只做减法，**两端字段有任何差异都要写明**，只记降级会造成「移动端 = PC 减一刀」的错觉
- 两端**数据条数**不一致时（线上实测：PC 8 张卡/移动 6 张，甚至移动端反而多 1 条——两套模板各自取数）既不是分页语义也不是隐藏，必须在声明里写明，禁止默认两边一样
- `degrades` 非空时，交付说明必须逐条复述降级清单让用户确认——**降级本身合法（见 §1），没写才不通过**

## 4. 替换模式库（PC 形态 → 移动形态的推荐对照）

> 来源：多站代码普查 + 线上 30 页截图比对收敛。选型时**先从本表取**，表里没有的才自定义（需标注确认）。

| 能力 | PC 形态 | 推荐移动形态 | 备选 | 已验证场景 |
|---|---|---|---|---|
| 筛选区 | 平铺 Radio/Toggle | **ODialog 抽屉**（筛选按钮唤起，含重置/确定） | OLayer 全屏二级页（带返回，筛选项多时） | 开发者门户下载页；资讯列表筛选收底部弹层 |
| 筛选状态可见性 | 已选条件 chips 常驻 | （反面警示）入口收成漏斗图标后**已选条件看不见了** | — | 线上查询页：筛选收成图标但已选状态无处展示——选型时必须给已选条件留个可见的载体 |
| 分页 | OPagination | **触底加载** | 「查看更多」按钮（弱浏览场景） | 资讯列表（12 条/页 ↔ 6 条/批成对修改）；注意降级有「装不下才降」和「到点就降」两种成因（§2.2 #6） |
| 数据窗口 | 按页切片 `slice((p-1)s, ps)` | 累计切片 `slice(0, ps)` | — | 触底加载的标配语义，和分页形态**必须成对**改（含两端每批条数） |
| 导航层级 | Tab / 侧栏 Menu | **OTab 顶部页签** | Select 下拉（弱导航）；手风琴（含子步骤的流程）；「标题+胶囊+⌄」折叠选择器（5 个 tab 的场景） | 个人中心页（页签+路由跟随）；多步流程页 |
| 弹窗 | ODialog | **独立页面**（路由级） | ODialog 底部半屏（轻量确认） | 线上「≤600 弹窗一律改页」策略 |
| 表格 | OTable | **卡片流：表头当 label**（每行一张卡，空值也渲染标签行，字段和 PC 完全一致——最干净的等价） | ①保表格 + 右列固定 + 横向滚动（列不裁）②折叠行 +「查看完整」外链（逐级减信息+外链补全）③宽表整块消失（须进 degrades）④数据 ≤4 条直接换卡片不换布局 | 兼容性查询页（表头 label 正面）；模型查询页（固定列横滚）；产品对比页（折叠行+外链） |
| 目录树 | 常驻左列（fixed，含收起手柄） | **两档抽屉**：840 推挤式（无遮罩、正文右移）/ 600 覆盖式 + 灰遮罩（70vw）；树内容不精简要二次滚动，宜评估精简 | 分组折叠 | 文档详情页（线上两站逐像素同构） |
| 页内工具栏 | 宽文字卡 | **三级降级**：文字卡 → 中档收窄成图标竖条 → 移动端少项浮栈（每一级丢的项都要逐项进 degrades） | — | 文档详情右侧工具栏（调查/助手/评分/提单/求助五项分三级） |
| Banner 大图 | BannerLevel2 | **简版 banner**（标题+单图） | 整图变链接（CTA 删，须声明）；「露出邻卡边缘」表达可滑动（两端裁切即暗示可滑，不用箭头） | 首页轮播（指示器换短横线） |
| Hero 主按钮 + 倒计时 | banner 上主按钮 + 倒计时面板 | **底部常驻操作条**（标题 + 剩余时间 + 主按钮合并迁移，信息不丢） | — | 活动详情页（正面范本）；论坛帖固定发表条同族 |
| Stepper 多步流程 | 横向步骤条 | **手风琴**（子步骤按需挂载，首项默认展开，文案和 PC 逐字对应） | — | 报名/申请流程页 |
| 流程图 | 箭头流程图（横链+分支） | **时间轴**（圆点+竖线+缩进表层级）；节点可用性用字重/颜色深浅在两种形态下保持一致的编码；手风琴头部可补「N 个场景」节点数 | — | 成长路径页（同一份流程图数据渲染成两种形态） |
| 架构图 | 图标+名称多列网格 | 纯文字 3 列网格 → 层级条 +「查看完整架构图 ›」外链（**逐级减信息 + 外链补全**） | — | 技术架构楼层 |
| 去 CTA 化 | 文本链 CTA（查看详情等） | 删文本链改**整卡可点**——更简洁但更难发现；须核对**出口完整性**（有内容没出口的纯展示块是失败态） | — | 线上贡献路径楼层（去 CTA 后没出口的反面教材） |
| 显式降级提示 | （无替代物时）直接砍 | 移动端新增「**请前往 PC 端**」提示——把降级说出来的 UI，degrades 字段的线上同款 | — | 线上认证页（全部样本里唯一的正面例） |
| 图片资源 | PC 尺寸图 | `<picture media>` 分档图（840 档）；只压高度不去除；缩略图两种策略：等比缩 vs 锁定尺寸（文字区域吸收宽度差，极窄时标题截断） | — | banner 分档（内容模型层）；新闻卡锁图 |
| 楼层容器 | 一块大白面板包多模块 | 拆成独立卡片 + **补楼层标题**（PC 上没有标题的子模块，移动端补一个显式标题） | — | 开发者门户工具/资源区 |
| 双栏图文 | 左文右图 | 图通栏 + 文字叠加（用可读性换版式）；图**提到文字上方**（顺序重排，不是往下挪） | — | 首页营销楼层 |
| 卡片内布局 | icon 左 + 横排文案 | 居中图标塔（icon 上、标题下）——同一数据两套卡版 | — | 开发者门户入口卡 |
| 移动端反向增强 | — | 独有 tab、补的楼层标题、发帖悬浮按钮（未登录时比 PC 入口更显眼） | — | 博客列表（移动独有「推荐」tab） |

**选型纪律**：
- 同一页面内**同一能力只用一种形态**（反面教材：同一站的触底加载同时存在 5 种实现）
- 模式库形态写进楼层工单后就是该楼层的**唯一规格**，验收按此核对

## 5. 验收口径（换版维度的检查项）

叠加在 SKILL.md 第六步自检之上，含 `adaptive` 声明的楼层必查：

```
□ 断点是不是声明的值（840/600/840+600）？把渲染窗口调到断点 ±1px，两侧形态是否正确切换？
□ 逐档重载：每档截图前必须整页重新加载——只改窗口宽度不重载，页面会停留在旧模板
  （实测 375→1080 不重载仍渲染移动版）、继承抽屉展开态，测出假结果
□ capabilities 表逐项核对落地（缺一项即不通过）；反向增强项同样逐项核对
□ 隐藏的能力逐条核对：有替代物 → 验证替代物是否等价；无替代物 → 验证是否进了 degrades
  （降级合法，没写才不通过）
□ 841–1200 区间是不是「PC 结构 + 流式」？（无移动形态提前/滞后触发）且表格/宽组件无挤压断词、逐字竖排
  （中间带可读性专项）
□ 分页形态切换时数据窗口语义是否成对？（切片方式、两端每批条数、两边条目数是否一致及是否已声明）
□ 双断点换版（840+600）时，600 线是否只做交互差异或声明过的功能二档形态，不重换布局？
□ 渲染验证宽度覆盖：五个断点档各档内部任取一个宽度 + 断点两侧各断点值 ±1px 截图；应用壳内滚容器需先探测
  （文档壳 window 不滚，整页截图只有视口高）
□ 验收截图必须是有内容的状态：空态/加载中不作换版证据；截图只能证明形态不能证明行为——
  能不能横滑、触底是否真的加载、抽屉里有什么，必须实际操作验证
```

## 6. 设计侧「换版声明」与工程侧的对接

| 本文件定义（设计侧） | 工程侧承接（opendesign-application） |
|---|---|
| `adaptive.breakpoint`（断点） | `useScreen` 派生值（`lePadV`/`isPhone`）或 `respond('<=pad_v')`，**两侧数值必须同源**（840/600） |
| `capabilities[].mobile` | 模式库条目的实现（Mo 组件 / ODialog / 触底指令等） |
| `degrades` | 降级声明写进代码注释（`<!-- 降级：锚点导航，理由：… -->`）——注释写的是**设计决策和理由**，禁止无注释的 display:none |
| 五断点档 + 断点 ±1px 验收（逐档重载） | 渲染验证宽度清单（同源同值；测试脚本各档独立加载而非只改视口） |

> 工程侧的派生值（`lePadV` 等）是**站内私有 API**，禁止跨站复制（跨站拷贝导致编译失败、被迫注释近百行代码的实例）；跨站复用走组件库沉淀（换版组件在单站内实现成熟后抽进组件库的轨迹）。
